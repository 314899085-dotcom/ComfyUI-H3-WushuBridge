# 安装与接线

## 1. 安装

```text
ComfyUI/custom_nodes/ComfyUI-H3-WushuBridge/        ← 把整个目录放这里
```

依赖：`torch`、`numpy`、`safetensors`。ComfyUI 环境里本来就有，**不需要额外 pip install**。

重启 ComfyUI。节点出现在 **MiniMax H3/Wushu Bridge** 分类下。

首次运行会自动创建：

```text
ComfyUI/models/wushu_bridge/             权重目录（桥 + 评分头）
ComfyUI/models/wushu_bridge/datasets/    训练数据集
```

装完自检（不需要 H3、不需要显卡）：

```bash
python ComfyUI/custom_nodes/ComfyUI-H3-WushuBridge/tools/selftest.py
```

八项全过会打印 `自检全部通过`。它用合成 embedding 把
「造训练对 → 建数据集 → 训桥 → 训评分头 → 应用 → 存取权重 → 维度保护」跑一遍。

## 2. 接线：怎么"夹在 conditioning 之间"

这个节点是纯 **CONDITIONING → CONDITIONING**，只替换 embedding 张量，
`minimax_keyframes` / `minimax_refs` / `minimax_frame_count` 等 metadata **原样保留**，
所以任何位置都能插，不会弄丢首尾帧或参考图信息。

### 2.1 文生视频（最简）

```text
[Load CLIP (H3)] ──► [CLIPTextEncode / H3 提示词节点] ──► [H3 武打语义逻辑桥] ──► [KSampler / H3 采样]
                                                                  │
                                                                  └─► report（STRING）：看漂移与评分
```

### 2.2 首帧 / 尾帧（FL2VA）

```text
[H3 首尾帧 conditioning 节点] ──► [H3 武打语义逻辑桥] ──► [KSampler]
```

首尾帧的 latent 在 metadata 里，不受影响。建议 `alpha` 从 0.10 起。

### 2.3 多参考图（Ref2VA）—— 保守接法

```text
[Load CLIP] ──► [H3 参考图 conditioning 节点] ──► [H3 武打语义逻辑桥] ──► [KSampler]
                          │                              ▲
                          └──► [CLIPTextEncode 纯文本同句] ─┘
                               (可选) 接到 H3 文本 token 段定位 看文本段位置
```

参考图模式下打包序列里混着参考图 token，位置不稳定。建议：

* `alpha` ≤ **0.12**
* `token_span` = **tail**，`tail_ratio` = 0.3~0.5（只改尾部，尽量只动文本）
* 打开 `guard`，改坏了自动回退
* 想更稳就先用 `H3 武打桥 采集训练对` 采一批**含 ref token 的真实 conditioning**，
  单训一个 ref2v 专用桥，再和文生视频那个桥分开用

### 2.4 串多个 conditioning（正/负、多段）

节点对 `conditioning` 列表**逐段**处理，每段独立报告 token 数与漂移。
负向 conditioning 一般**不要**过桥（桥是往"逻辑完备"方向推的，负向不需要）。

## 3. 参数怎么调

| 参数 | 建议 | 说明 |
|---|---|---|
| `alpha` | **0.12** 起，A/B 试 0.08 / 0.12 / 0.20 | 融合强度。0＝完全不动，1＝完全替换（不推荐） |
| `magnitude_match` | `per_token` | 逐 token 把幅度对齐回原序列，防止能量漂移 |
| `token_span` | 文生/首尾帧 `all`；参考图 `tail` | 参考图模式不要全序列硬改 |
| `chunk_tokens` | 0（不分块）；显存紧或 CPU 跑时设 512~1024 | Transformer 桥对超长序列分块前向 |
| `judge` | 选你的评分头 | 用于自动调 alpha、守护、分数报告 |
| `auto_alpha` + `auto_alpha_max` | 开，0.25 | 逻辑分低就多修，分高就几乎不动 |
| `guard` | 开 | 改完评分反而更低 → 自动回退为原 conditioning |
| `allow_dim_mismatch` | 关 | 开着会把维度不符的段跳过而不是报错（多桥混用时方便） |

### 怎么判断"有没有效果"

节点 `report` 输出给了两个数：

* **语义漂移 (1-cos)**：改动幅度。建议 **< 0.15**。超过 0.3 基本就是在乱改了。
* **改动前后逻辑分**：评分头给的武打逻辑概率。涨了才说明桥在干正事。

最终还是要出片对比：同一 seed、同一提示词，`alpha = 0 / 0.12 / 0.2` 各跑一条。

## 4. 常见问题

**Q：报错「维度不匹配：conditioning dim=4096，桥 dim=5120」**
桥是在另一个文本编码器上训的。H3 的 conditioning 是 5120 维；4096 说明你接的是别的模型
（或别的 CLIP 加载器）。用 H3 那套 CLIP 重新建数据集并训练。

**Q：`bridge` 下拉只有一句"(还没有桥权重…)"**
还没训练。先跑 `H3 武打桥 训练残差桥`，或者把别人的 safetensors 丢进
`ComfyUI/models/wushu_bridge/` 再点 ComfyUI 右上角刷新。

**Q：能直接用社区那 11MB 的 `MiniMaxH3_SemanticBridge_v1.safetensors` 吗？**
能。把 `arch` 选 `mlp` 的场景下它是同构的；加载器会自动识别权重形状（不依赖元信息），
放进 `models/wushu_bridge/` 就能在 `bridge` 下拉里选到。它做的是通用语义对齐，
不是武打逻辑——适合当**对照基线**。

**Q：训练节点卡在"开始编码 N 条文本"很久**
正常。H3 文本编码器要逐条编码。924 条语料 × 4 个变体 ≈ 3700 次编码。
先用 `max_pairs=200` 跑通流程，再放大。

**Q：数据集文件好大**
真实 H3 conditioning 的 token 数远大于演示文本。用 `max_pairs` 控制规模；
文件是 fp16 + 压缩存储，几百对大约几百 MB。

## 5. 打包带到别的机器

```bash
python ComfyUI/custom_nodes/ComfyUI-H3-WushuBridge/tools/make_package.py
# 产出 ComfyUI-H3-WushuBridge-0.1.0.zip（约 130 KB）
```

zip 里排除了 `__pycache__`、权重、数据集与差分验证用的 JS 临时副本。
解压到目标机器的 `ComfyUI/custom_nodes/` 下即可，重启 ComfyUI 生效。

**训练好的权重要单独拷**（体积太小，直接复制就行）：

```text
ComfyUI/models/wushu_bridge/*.safetensors          ← 桥 + 评分头
```

数据集（`models/wushu_bridge/datasets/*.npz`）**不必**拷到别的机器——
它跟那台机器的 H3 文本编码器绑定，换机器要重新建。

### 换机器后的验证顺序

```bash
# 1. 环境自检（不需要 H3、不需要显卡）
python ComfyUI/custom_nodes/ComfyUI-H3-WushuBridge/tools/selftest.py

# 2. 单测（可选，需要 pytest）
python -m pytest ComfyUI/custom_nodes/ComfyUI-H3-WushuBridge/tests -q

# 3. 规则引擎差分验证（可选，需要 node；确认移植版与 h3lint.js 一致）
python ComfyUI/custom_nodes/ComfyUI-H3-WushuBridge/tools/run_h3lint_diff.py
```
