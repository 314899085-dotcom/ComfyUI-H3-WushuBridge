## 四、最重要的记录发现：杠杆在「训练对」，不在「桥」

在**真 H3 embedding** 上测出来的指标：

| 配置 | bad/good 池化相似度 | **方向对齐度** | relative_gain |
|---|---|---|---|
| 降级强度 **3**（删 1–2 句） | 0.9962 | **0.046** ← 等于噪声 | 0.00022 |
| 降级强度 **5**（整个逻辑层重写） | 0.9969 | **0.434** ← 9 倍 | 0.00026 |

**解读**：删掉一两句话，对一段 250 token 的提示词做池化余弦后只差 **0.4%**——
桥根本没有可学的方向，`relative_gain` 趋近于 0 是必然的。
把降级做狠（抽力线 + 抽格距 + 抽防守 + 抽打击反馈 + 泛化招式 + 破坏结局）之后，
方向对齐度跳到 0.43，桥才开始真的学到东西。

所以插件里新增了两个**每次训练都会报**的指标，用来判断数据够不够狠：

* `bad_good_similarity`：正负例有多像。**越接近 1，说明降级越没用**
* `direction_alignment`：桥的移动方向与 (good − bad) 方向的一致度。**这才是有效信号**

判读标准（记录经验）：`direction_alignment < 0.15` 基本等于没学；`> 0.35` 才算真的学到。

## 五、在真机上才暴露的 5 个 bug（已全部修复 + 加回归测试）

| # | 现象 | 根因 | 影响 |
|---|---|---|---|
| 1 | `prompt_no_outputs: Prompt has no outputs` | 报告类节点没声明 `OUTPUT_NODE = True` | **用户无法单独运行数据集/训练节点** |
| 2 | `element 0 of tensors does not require grad and does not have a grad_fn` | **ComfyUI `execution.py:751` 用 `torch.inference_mode()` 包住节点执行**；inference_mode 内的张量不追踪梯度，而 `torch.enable_grad()` **无法**抵消它 | **两个训练节点 100% 崩溃，插件等于废的** |
| 3 | `Expected all tensors to be on the same device, but found cuda:0 and cpu` | conditioning 在 CPU、桥权重在 GPU，`magnitude_match` 跨设备 | 桥节点第一次用就崩 |
| 4 | `wrapper_CUDA_clamp_min__Tensor: min is on cpu` | 漂移计算里 `F.cosine_similarity` 内部的 clamp_min 跨设备（修完 3 才暴露） | 同上 |
| 5 | 报告里「改动前」打印两次 | `report.messages` 被拼了两遍 | 小瑕疵 |

**修法要点**（写在这里防止以后踩回去）：

```python
# 2) 训练函数必须显式退出 ComfyUI 的 inference_mode
with torch.inference_mode(False), torch.enable_grad():
    ...训练代码...

# 3/4) conditioning ↔ 权重的设备对齐，算完再搬回来
h_dev = h.to(device=device)                  # 桥所在设备
pred = bridge(rms_normalize(h_dev[...]))
hybrid = h_dev.clone()
...
result.append([hybrid.to(device=native.device, dtype=native.dtype), new_meta])
```

新增 `tests/test_comfyui_contract.py` 把这几条固化（在 `torch.inference_mode()` / `torch.no_grad()`
里各跑一次训练），以后改动不会再退化。

## 六、接好后的工作流长什么样

最小可跑的三节点图（桥是链路中段节点，末端必须接一个 output 节点）：

```text
[CLIPLoader]                type = minimax
  clip_name = qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors
        │
        ▼
[CLIPTextEncode]            或 H3 自己的 conditioning 节点（含参考图/首尾帧）
        │
        ▼
[H3 武打语义逻辑桥]          bridge=你的权重  alpha=0.15  judge=你的评分头  guard=开
        │
        ▼
[H3 武打逻辑评分]            ← 终端节点，节点上直接显示分数
```

桥节点自己的 report（**已做到节点上直接可见，不用再接文本显示节点**）：

```text
武打语义桥：应用 1 段 conditioning，跳过 0 段
  #0: dim=5120 tokens=265 语义漂移(1-cos)=0.0156
改动前武打逻辑分：0.540
改动后武打逻辑分：0.664
```

**语义漂移建议 < 0.15**；超过 0.3 基本就是在乱改，把 `alpha` 降一半。
