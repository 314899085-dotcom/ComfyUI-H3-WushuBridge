# ComfyUI-H3-WushuBridge 使用指南

> **一句话**：这是一个「**武术动作导演 + 武打语义桥**」插件。
> **编排层**决定*打什么*（谁出招、怎么接、打中什么反应、追击连招、道具破坏），
> **语义桥层**决定*怎么说*（把 conditioning 往武打逻辑分布推），
> **规则层**决定*合不合格*（用你的 h3lint 规则引擎体检）。
>
> 配套：MiniMax-H3（海螺 H3）｜触发词 `wushu_action`｜支持 wushu_h3_v2 / v7 两类 LoRA

## 1. 这是什么

### 1.1 三层分工（关键概念）

```text
[H3 武打编排（动作导演）]  ← 编排层：状态机决定每一拍谁打谁、怎么防、什么结果
          │ prompt
          ▼
   [CLIPTextEncode]
          │ CONDITIONING
          ▼
[H3 武打语义逻辑桥]        ← 语义桥层：在 5120 维条件空间微调语义（不改文本）
          │ CONDITIONING
          ▼
      [采样器]
          ▲
[H3 武打逻辑评分]          ← 评分层：不吐字，直接给 0~1 的武打逻辑概率
[H3 武打提示词体检]        ← 规则层：h3lint 八维体检，出分数与必改项
```

**为什么分两层**：文本层能表达的是「写了什么」，而 H3 真正吃进去的是 5120 维语义。
规则能查"写没写格距"，查不了"算得对不对"（格距是否等于攻击距离、每秒额度、血线结算、死线胜负
——这些的真值在你的 `sim3d/engine.js` 60Hz 结算里）。所以：

* **能写清楚的** → 编排层用状态机算准再写成文本；
* **写不出来的那部分语义** → 用语义桥在 embedding 空间里补。

### 1.2 编排层覆盖了什么

| 你要的 | 实现 |
|---|---|
| 什么时候出招 / 对手什么时候接 | 主动权(initiative) + 每拍攻守决策；够不到先走步（距离纪律） |
| 击中后的反应与击打反馈 | 4 档：轻（闷响、碾半步）/ 实（衣料撕裂、踉跄退一格）/ 重（单膝着地）/ 终结（脱手、沿作用线倒地） |
| 追击、连续出招 | 命中造成硬直，攻方在硬直内追击；**最多连 2 下**，第三下强制换手 |
| 防守后反击 / 闪避后反击 | 连格达阈值 / 连闪达阈值 / 对方落空 → 反击窗口，主动权交换 |
| 不同招式的拼接 | 连段（压制 → 换位 → 终结），同一串内距离不跳变 |
| 打碎物品、墙体 | 三种触发：**劈空**劈进实体 / 被格挡**磕飞**扫到旁边 / 被击退**撞上**。扣耐久，破了留痕且**跨镜保留不复原** |
| 完整打斗逻辑 | 死线必有可见结果；因果链闭合；音景按材质（徒手不写金属声）；切镜重申"同一两人" |

## 2. 安装

### 2.1 三步

```text
① 解压 ComfyUI-H3-WushuBridge-0.1.0.zip
   → 得到 ComfyUI-H3-WushuBridge 文件夹
   → 整个放进 <你的ComfyUI>\custom_nodes\

② 两个权重复制到 <你的ComfyUI>\models\wushu_bridge\
   wushu_bridge_wushu_v1.safetensors   16.05 MB
   wushu_jev_wushu_v1.safetensors       6.51 MB

③ 重启 ComfyUI
```

```powershell
# ② 的复制命令（把 <ComfyUI> 换成你的路径）
$dst = "<ComfyUI>\models\wushu_bridge"
New-Item -ItemType Directory -Force $dst | Out-Null
Copy-Item D:\Wushu\ComfyUI-H3-WushuBridge\models\wushu_bridge\*.safetensors $dst
```

### 2.2 ComfyUI 是怎么"加载"它的

**没有安装动作、没有配置文件、不用 pip install**（依赖 torch/numpy/safetensors ComfyUI 自带）。
ComfyUI 启动时扫 `custom_nodes/` 每个子目录，import 它的 `__init__.py`，读两个字典：

```python
NODE_CLASS_MAPPINGS        # 节点内部名 → 类（本插件 11 个）
NODE_DISPLAY_NAME_MAPPINGS # 显示名（菜单里看到的中文名）
```

所以唯一容易错的是**目录层级**：必须是

```text
custom_nodes\ComfyUI-H3-WushuBridge\__init__.py        ✅
custom_nodes\ComfyUI-H3-WushuBridge\ComfyUI-H3-WushuBridge\__init__.py   ❌ 多套一层
```

### 2.3 装完的三项验证

| # | 方法 | 期望 |
|---|---|---|
| A | 用 ComfyUI 的 python 跑 `python tools\run_all_checks.py` | 最后一行「全部通过」 |
| B | 节点菜单搜「武打」 | 能找到 **11 个**节点，分类 `MiniMax H3/Wushu Bridge` |
| C | 启动日志搜 `WushuBridge` | 有一行 `0.0 seconds: .../ComfyUI-H3-WushuBridge`；出现 `IMPORT FAILED` 就是失败 |

> **权重没放也能用**：桥/评分头节点的下拉框里只会显示占位提示，不报错。
> **纯规则的两个节点（武打编排、提示词体检）完全不需要权重** —— 解压完就能用。

## 3. 三条上手路径

### 路径 A：只用编排层（**不需要任何权重，装完就能用**）

```text
[H3 武打编排（动作导演）] → report 里直接看逐拍 + 提示词
                          → prompt 接给任意 CLIPTextEncode
```

适合：快速产出打斗分镜脚本、给 AI 润色当输入、验证打斗逻辑。

### 路径 B：编排 + 规则体检

```text
[H3 武打编排] ─prompt─┬─→ [CLIPTextEncode] → 采样器
                      └─→ [H3 武打提示词体检] → score / grade / report
```

适合：想先看分数（≥90 且零必改）再出片。

### 路径 C：完整链（推荐）

```text
[H3 武打编排] --prompt--> [CLIPTextEncode] --cond--> [H3 武打语义逻辑桥] --cond--> 采样器
                                                            ▲
                                                    [H3 武打逻辑评分]（终端，显示分数）
```

桥的参数起始值：`alpha=0.15`、`magnitude_match=per_token`、`token_span=all`、
`judge=wushu_jev_wushu_v1`、`guard=开`（改坏了自动回退）。

## 4. 节点逐个说明

> 所有"报告类"节点都是 **output 节点**，报告直接显示在节点上，**不需要再接文本显示节点**。

### 4.1 `H3 武打编排（动作导演）`

产出完整打斗编排 + 可直接用的 H3 提示词。

| 输入 | 默认 | 说明 |
|---|---|---|
| `角色A` / `角色B` | 见下 | 角色卡，格式 **`武器\|等级\|外貌\|招式1,招式2`** |
| `场景` | 雨夜长街… | 写进提示词头部，同时决定"为实体"的物件 |
| `地面` | 湿石 | 湿石/夯土/木地板/雪地/石砖 —— 影响音景与打滑描写 |
| `道具` | 灯笼柱;木栏 | 格式 **`名称\|耐久\|破坏表现`**，分号分隔；留空=没有可破坏道具 |
| `时长秒` | 10.0 | 3~60 |
| `分镜数` | 3 | 武打默认 1~3 镜；4 镜起规则引擎会给警告 |
| `模式` | t2v | **t2v（文生视频）/ ref2v（多参考图）—— 两套壳字段不同，绝不能混用** |
| `编排类型` | 对打（双人） | 另有「单人演练（对齐 wushu_h3_v2 分布）」 |
| `招式词库` | **LoRA 实证词** | 另可切「自造招式名（v7 影视向）」 |
| `开场间距` | 2.0 | 格 |
| `指定赢家` | 自动按血量判定 | 或指定角色A/角色B |
| `进攻性` | 0.62 | 越高越倾向放招式而非普攻 |
| `种子` | 1234 | 同种子=同编排，可复现 |
| `参考图张数` | 3 | 仅 ref2v |
| `规则自检` | 开 | 生成后自动跑 h3lint，报告里给分数与必改项 |

**角色卡写法**：

```text
武器：中文名或引擎 key 都行 —— 太刀/nodachi、刀/dao、剑/jian、枪/qiang、
      棍/gun、棒/bang、朴刀/pu、短棍/duangun、短刃/duanren、空手/none
等级：1~9（影响伤害与机动档）
外貌：发色+发型+服装+体型+兵器（越具体越不容易换人）

例：nodachi|4|男性，黑发披散，黑色武士劲装，双手持野太刀|过肩劈,横扫,突刺
```

**三个输出**：

* `prompt` — 完整 H3 提示词（可直接进 CLIPTextEncode；超长会自动切段）
* `beats_json` — 逐拍结构化数据（谁打谁/防守/结果/道具），可接显示节点
* `report` — 编排摘要 + 逐拍表 + 道具留痕 + 规则引擎自检分数

### 4.2 `H3 武打语义逻辑桥（接在 conditioning 之间）`

| 输入 | 默认 | 说明 |
|---|---|---|
| `conditioning` | — | 上游 conditioning |
| `bridge` | — | 桥权重 |
| `alpha` | 0.12 | 融合强度。**实测 0.15 时语义漂移仅 0.010**，很保守；想加强试 0.2~0.25 |
| `magnitude_match` | per_token | 逐 token 把幅度对齐回原序列（推荐） |
| `token_span` | all | `all` 全序列（文生/首尾帧）；**参考图模式改 `tail`** |
| `tail_ratio` | 1.0 | `token_span=tail` 时只改尾部这个比例 |
| `chunk_tokens` | 0 | >0 时对超长序列分块前向 |
| `judge` | none | 选评分头 → 报告里出"改动前后逻辑分" |
| `auto_alpha` | 关 | 逻辑分低就自动多修一点 |
| `guard` | 关 | **改完评分反而低就自动回退**（强烈建议开） |

**输出**：`conditioning` / `report` / `logic_score`

报告长这样：

```text
武打语义桥：应用 1 段 conditioning，跳过 0 段
  #0: dim=5120 tokens=265 语义漂移(1-cos)=0.0156
改动前武打逻辑分：0.540
改动后武打逻辑分：0.664
```

> **语义漂移建议 < 0.15**；超过 0.3 基本就是在乱改，把 `alpha` 降一半。

### 4.3 `H3 武打逻辑评分（JEV 式）`

不吐字，直接给 0~1 概率。输入 `conditioning` / `judge` / `aggregate`（mean/min/max）/ `threshold`；
输出 `score` / `report` / `pass`。可当筛选开关用。

### 4.4 `H3 武打提示词体检（规则引擎）`

`h3lint.js` 的 Python 移植，八维体检（内容结构/运动节奏/音频/物理逻辑/人物真实感/风格一致性/对白/打斗连贯性）。

* `text` 粘稿子；`mode` = final（成品稿）/ design（设计稿）
* `score_mode` = composite（推荐，0.4×壳结构 + 0.6×武打逻辑）/ logic / lint
* 输出 `score` / `grade` / `report`

### 4.5 `H3 武打桥 降级预览`

看一条正例被降级成什么样（造训练对用）。`intensity` 1~5，**5 = 整个逻辑层重写**。

### 4.6 训练三件套（一般不用跑，权重已经训好了）

| 节点 | 用途 |
|---|---|
| `构建数据集（用 H3 文本编码器）` | 你的语料 → 训练对 → `*.npz` |
| `训练残差桥` | 训桥；看 `relative_gain` 与 `direction_alignment` |
| `训练 JEV 评分头` | 训评分头；看 `val_accuracy` / `AUC` / `ECE` |
| `采集训练对（从真实 CONDITIONING）` | 参考图模式：采含 ref token 的真实样本 |
| `清空缓存` | 换权重后清显存 |

**训练链的四个卡点**（每个都有硬指标）：

| 步骤 | 通过标准 |
|---|---|
| ① 建数据集 | 维度 = 5120；正例均分 > 负例均分 |
| ② **人工抽查** `*_pairs.jsonl` | `bad`/`good` 是**同一场景同一人物**，只差动作逻辑 |
| ③ 训桥 | `relative_gain > 0`、**`direction_alignment > 0.35`**、`drift < 0.15` |
| ④ 训评分头 | `AUC > 0.85`、`ECE < 0.1` |

> **实测经验（很重要）**：降级强度 3 时 `direction_alignment` 只有 **0.046**（等于没学）；
> 强度 5 时升到 **0.43**；强度 5 + 676 对时到 **0.764**。
> **杠杆在"训练对造得多狠"，不在"桥多大"。**

## 5. 和 LoRA 配合

### 5.1 两类 LoRA 不要混用

| | **wushu_h3_v2**（人体动作本体） | **wushu_action_v7**（影视成片） |
|---|---|---|
| 训练素材 | 1668 段人体模型三视图动画 | 924 段真实武打影视片段 |
| 学到 | 纯运动学与发力传导 | 成片画风 + 招式术语 + 镜头感 |
| 提示词分布 | **固定模板 + 单/多个招式词** | 三段式分镜 `[Shot 1/2/3]` |
| 适用 | 动作参考 / 动作先验 | 直接出片 |

**v2 不能用 v7 那套 `[Shot 1/2/3]` 分镜模板**——它没见过这种 caption 结构。
所以本插件里有个开关：`招式词库 = LoRA 实证词（wushu_h3_v2 训练集）`。

> ⚠️ **两个 LoRA 触发词相同（都是 `wushu_action`）**，同时挂载会互相打架。
> 建议只挂一个为主，另一个强度压到 0.3 以下。

### 5.2 v2 的**实证招式词**（用这些词命中率远高于自造词）

插件已内置 **32 条 / 12 类**，括号是训练集出现次数：

| 类别 | 词 |
|---|---|
| 拳法 | 蹬地打直拳(37)、后手横拳、抡臂横勾、上勾拳 |
| 腿法 | 高侧踢(24)、提膝撞击(8) |
| 步法 | 稳步前进(108)、疾步冲刺(79)、转身换向(7)、下蹲低姿、急速冲刺 |
| 受击 | 踉跄后退(69)、失衡踉跄(7)、反弓跌落、团身翻滚 |
| 刀剑 | 横斩劈砍(35)、突刺贯穿(50)、双持交叉斩(10)、横扫(7) |
| 棍棒 | 转棍扫击(10) |
| 远程 | 举弩瞄准、脚踏上弦装填、松手放箭 |
| 防御 | 举盾格挡(54)、侧身格挡反击、侧闪回避(24) |
| 摔投 | 过肩摔投(7)、锁颌下坠 |
| 空中 | 腾空跃起(67) |
| 节奏 | 呼吸站姿微动(41) |
| 通用 | 连续连招(239)；**`战斗动作`(232) 是泛化占位词，别用** |

选中 `LoRA 实证词` 后，引擎会：招式名/防守词/受击反馈词全部换成实证词，
并自动带上固定物理反馈词 **`实时爆发力、全身发力传导、无慢动作、无停顿`**
（这几个词参与塑造动作质量，去掉会掉效果）。

### 5.3 `单人演练` 模式（v2 的**分布内**用法）

v2 训练集是**单人体操模型**，**双人对它属外推**。所以插件提供：

```text
编排类型 = 单人演练（对齐 wushu_h3_v2 分布）
```

输出直接是它的模板式写法：

```text
wushu_action, 男性，黑发披散，黑色武士劲装，双手持野太刀,
后手横拳、高侧踢、下蹲低姿、突刺贯穿, rear-hand cross, high side kick, ...,
实时爆发力、全身发力传导、无慢动作、无停顿, indoor training hall, fixed full-body camera, 16:9
```

**要正常画面 + 武打动作**（v2 用法 B）：主动写出主体和场景 + 保留物理反馈词 + LoRA 强度降到 **0.6~0.8**。

### 5.4 强度速查

| 场景 | LoRA 强度 |
|---|---|
| v2 复现三视图动作参考 | 0.9 ~ 1.0 |
| **v2 正常画面借动作（推荐起点）** | **0.7** |
| v2 画风干扰太强 | 0.5 ~ 0.6 |
| v7 直接出片 | 0.7 ~ 0.9 |
| 动作不够"武" | 1.0 ~ 1.1（超 1.1 易崩） |

## 6. 参数速查

### 6.1 H3 采样参数（照抄，别乱改）

| 参数 | 值 | 说明 |
|---|---|---|
| sampler / scheduler | `euler` / `simple` | H3 上最稳 |
| steps | 25 | 用 turbo 底模则 4~8 |
| **cfg** | **1.0** | ⚠️ H3 是 CFG 蒸馏模型，`>1` 必出坏图 |
| denoise | 1.0 | — |
| 分辨率 | 832×480 | 必须是 **32 的倍数** |
| fps | 24 | — |
| **帧数** | **必须 17n+5** | 22/39/56/73/90/107/124/175/243/362… |

### 6.2 时长 ↔ 帧数

| 时长 | 帧数 | 备注 |
|---|---|---|
| 1.3 秒 | 39 | v2 训练分布下界 |
| 3.0 秒 | 90 | v2 训练分布上界（**v2 优先用这个区间**） |
| 5.0 秒 | 124 | H3 常用 |
| 10.0 秒 | 243 | H3 常用 |
| 15.1 秒 | 362 | 提示词会超 2500 字，插件**自动切 2 段** |

### 6.3 语义桥

## 7. 完整实战流程

### 场景一：v7 出片（双人对打，10 秒）

```text
① [H3 武打编排]
   角色A = nodachi|4|男性，黑发披散，黑色武士劲装，双手持野太刀|过肩劈,横扫,突刺
   角色B = dao|3|男性，灰发束髻，靛蓝汉服武袍，右手持雁翎单刀|撩刀,反手削
   时长秒 = 10.0   分镜数 = 3   模式 = t2v
   招式词库 = 自造招式名（v7 影视向）
```

## 8. 排错表

| 现象 | 原因 / 对策 |
|---|---|
| 节点菜单一个都没有，日志 `IMPORT FAILED` | 目录层级多/少一层，`__init__.py` 不在顶层 |
| 一个节点都没有也没报错 | 放错 ComfyUI 了（有人机器上有两份） |
| 桥的下拉框只有占位提示 | 权重没放，或放完没点右上角**刷新模型列表** |
| `No module named 'safetensors'` | 用错 python（用了系统 python 而不是 ComfyUI 那个） |
| 报「维度不匹配：conditioning dim=4096」 | 桥是在别的文本编码器上训的；H3 是 **5120** 维，用 H3 那套 CLIP |
| 出图崩坏 / 色彩怪异 | `cfg` 是不是 >1？H3 必须 **1.0** |
| 帧数报错 | 必须 17n+5 |
| 分辨率报错 | 宽高必须是 32 的倍数 |
| 动作僵硬 / 有停顿 | 提示词漏了 `无慢动作` / `无停顿` |
| 桥看不出效果 | 看 `report` 的漂移值：<0.02 就调大 `alpha`；或看训练报告的 `direction_alignment` |
| 参考图模式掉人脸/掉服装 | `alpha ≤ 0.08`、`token_span=tail`、`tail_ratio=0.3` |
| 编排结果"未分胜负" | 不该出现；若遇到把 `时长秒` 调 ≥3 或换 `种子` |
| 提示词超 2500 字 | 插件会自动切段（每段单独提交，**上一段尾帧作下段首帧**）；也可把 `分镜数`/`时长秒` 调小 |

### 9.4 14 条核心打斗规则（自检 rubric）

1. **无因停顿禁令**：任何 >0.35 秒的静止都必须由受击硬直/闪避落位/被兵器压住/换架/绕步/掩体阻隔解释，并写成画面里的动作
2. **打斗反馈五要素**：前因、动作、接触点、受力方向与位移、余波与下一步的起因
3. **因果链闭合**：上一拍的结果必须是下一拍的起因
4. **连续招式**：收招后半段接下一招；同串连段距离不得跳变
5. **闪避必须指向具体来招**，写明落位，落位后必须出现反击或反压
6. **反击窗口**：格挡后 0.2~0.8s、闪避落位后 0.15~0.6s、对方落空后 0.15~0.5s
7. **主动权交换**：每 1.5~3 秒一次，写成谁退谁进、谁的兵器线压住对方
8. **距离纪律**：缩短必须先写脚步，拉开必须先写撤步或被击退
9. **高度与姿态**：至少各变化一次，且每次变化有受力或选择作为原因
10. **兵器与道具唯一性**：同一件兵器不得凭空出现第二把；被击落的兵器留在画面里
11. **间隙动作显性化**：让每一秒都有具体动作
12. **节奏红线**：首个有效动作 ≤0.3s；15 秒内交锋 6~9 次
13. **声音跟着受力走**：材质与声音对应，徒手不写金属声
14. **结束画面兑现完成条件**：胜负或脱离必须被画面看见

### 9.5 已知限制

* **双人对打对 wushu_h3_v2 是外推**（它只见过单人三视图）；要稳就用单人演练模式，或换 v7。
* **参考图（Ref2VA）模式保守**：社区版 v1 明确不支持，本插件默认同样保守（低 alpha + 只动尾部 token）。
* **语义桥是"引导"不是"重写"**：它只能沿学到的方向平移语义，不能删词加词。要真正改写文本那是编排层/润色层的事。
* **representation 指标不等于观感**：训练报告的 cosine / drift 只说明"有没有往目标方向走"，最终还要出片 A/B。
* 编排批量验收 **35/36** 达标（15.1 秒 + 某 seed 的分段后第 2 段偶发 `fight-no-counter`）；换 seed 或把时长压到 15 秒内即正常。
